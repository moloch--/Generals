## 2026-07-29: Restore the exploratory MinGW cross-build

Restored the Docker-based `mingw-w64-i686` path far enough to configure,
compile, and link both Windows game executables from an Apple Silicon macOS
host.

Build-system and portability work:
- Installed Wine's `widl` tooling in the MinGW image so CMake can generate the
  legacy COM interfaces.
- Made the MinGW preset select the native DirectX 8, Bink, and Miles path while
  disabling the SDL3, OpenAL, FFmpeg, MoltenVK, updater, and SagePatch paths.
- Corrected moved Windows input, audio, video, and VFW frame-grab source lists.
- Kept CompatLib's POSIX replacement headers out of native Windows compilation
  and repaired MinGW-specific socket, thread, floating-point, parsing, and CRT
  compatibility issues.
- Made the Docker wrapper work on Apple Silicon, use bounded parallelism, and
  fail when the expected PE artifact is absent.

Produced artifacts:
- `build/mingw-w64-i686/GeneralsMD/generalszh.exe`
- `build/mingw-w64-i686/Generals/generalsv.exe`

Validation:
- `GX_MINGW_JOBS=8 ./scripts/build/linux/docker-build-mingw-zh.sh mingw-w64-i686`
- Built the `g_generals` target in the same MinGW container and build tree.
- `file` identifies both outputs as PE32 GUI Intel 80386 executables.
- The executables do not dynamically import `libgcc`, `libstdc++`, or
  `libwinpthread`.
- `cmake --build build/macos-vulkan --target z_generals g_generals --parallel 8`
  passes as a native regression build.
- `git diff --check`, build-wrapper syntax validation, and CMake preset
  enumeration pass.

Runtime limitations:
- This validates cross-compilation and linking only; the binaries have not been
  launched on Windows or through a 32-bit Wine environment.
- The generated PE files still import `d3dx8d.dll`, which is not supplied by
  the retail installation.
- The pinned Bink and Miles import libraries use MinGW symbol decoration that
  does not yet match the retail DLL exports. Their generated DLLs are no-op
  link stubs and are not suitable for gameplay.
- The current target is the legacy 32-bit i686 Windows path, not a 64-bit
  Windows port.

## 2026-07-29: Port multiplayer discovery and frame-limit fixes

Integrated the functional networking changes from upstream
[LAN PR #181](https://github.com/fbraz3/GeneralsX/pull/181),
[POSIX discovery PR #201](https://github.com/fbraz3/GeneralsX/pull/201),
and this fork's [Apple interface PR #13](https://github.com/ammaarreshi/Generals-Mac-iOS-iPad/pull/13)
without importing their diagnostics, submodule moves, or retail-wire-format
changes.

LAN behavior:
- POSIX LAN receivers now bind to `INADDR_ANY` so broadcasts arriving on
  Wi-Fi or Ethernet are accepted. Debug multi-instance builds retain their
  distinct synthetic `127.x` bind addresses.
- LAN IP enumeration rejects down, loopback, point-to-point,
  non-broadcast, link-local, VPN, AWDL, and common container interfaces.
  The iOS Personal Hotspot `bridge100` interface remains eligible.
- Discovery packets use the selected interface's directed subnet broadcast.
  Post-join game options, readiness, chat, start, leave, and inactivity
  messages use per-peer unicast fan-out.
- Join accept/deny replies remain unicast to the requesting peer instead of
  being converted back into broadcasts.
- POSIX UDP errors now follow the same handling path as Winsock. Bind retries
  close their failed socket first instead of leaking descriptors.

Frame pacing:
- Ported the final behavior from
  [multiplayer FPS PR #230](https://github.com/fbraz3/GeneralsX/pull/230):
  LAN and GameSpy starts no longer disable the user's render cap.
- Initialized the tactical-view time multiplier and fixed the uncapped FPS
  sentinel comparison using upstream commit
  [`0cf00e606`](https://github.com/fbraz3/GeneralsX/commit/0cf00e606c8b10a95d59b377b445d932a5f9b87e).

iOS:
- Added a default-off `GX_IOS_MULTICAST=1` packaging option. It requests and
  verifies `com.apple.developer.networking.multicast`, which physical iOS
  devices require for UDP broadcast.
- The option intentionally fails closed when the signed provisioning shell
  lacks the entitlement. Apple must first approve Multicast Networking for
  the exact explicit App ID and the provisioning profile must be refreshed.

CRC review:
- Reviewed upstream CRC PR #189 and its later `Int`-based mapping. This fork
  already resolves a gameplay player to its network slot before checking
  connectivity, so no conflicting CRC dependency chain was imported.

Validation:
- `cmake --preset macos-vulkan`
- `cmake --build build/macos-vulkan --target z_generals g_generals --parallel 18`
- Deployed Zero Hour to `~/GeneralsX/GeneralsZH`.
- Launched the deployed `GeneralsXZH -win` build through SDL3, DXVK, Vulkan,
  and MoltenVK to a live game window.
- `git diff --check`, iOS entitlement plist validation, packaging-script
  syntax validation, and invalid-option handling all pass.

Remaining live coverage:
- A two-peer macOS/Linux test is still required to prove discovery, normal
  join, chat/readiness/start fan-out, disconnect handling, and a sustained
  no-desync match on a real subnet.
- Debug multi-instance LAN still needs a macOS loopback-alias or transport
  solution for instances after the first; normal release multiplayer is
  unaffected.
- The iOS entitlement path requires an Apple-approved App ID, refreshed
  profile, physical device, and second LAN peer before it can be
  device-verified.
