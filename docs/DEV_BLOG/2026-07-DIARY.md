## 2026-07-31: Package the macOS SFX as a proper app

Added a native macOS application bundle around the Go self-extracting Zero Hour
executable. The app keeps the SFX as its direct `Contents/MacOS/GeneralsXZH`
entrypoint, so Finder launches the same verified extractor without a shell shim
or a second implementation of game startup.

Packaging details:
- Added `package-sfx-macos-zh-app.sh`, with safe same-directory staging,
  copy-on-write cloning where APFS supports it, identifier-aware replacement,
  rollback preservation, and complete-tree publication to
  `build/sfx/GeneralsXZH.app`.
- Rejected app outputs inside the owned retail tree, nested raw/app outputs,
  symlink targets, foreign bundle identifiers, and parents that resolve to the
  filesystem root before destructive publication.
- Added a conventional plist, `PkgInfo`, ARM64 and macOS 15 metadata, strategy
  game category, high-resolution support, numeric bundle versions, and the
  existing `com.generalsx.generalsxzh.sfx` signing identifier.
- Converted the tracked 650x650 Zero Hour artwork into a real 3.58 MB `.icns`
  containing all ten standard and Retina representations from 16x16 through
  1024x1024, then round-trip validated every generated image dimension.
- Validated the direct app executable as ARM64-only, without `LC_RPATH`, with
  only `/usr/lib` or `/System/Library` dependencies and the expected embedded
  product, target, and entrypoint metadata.
- Removed copied extended attributes, signed the completed bundle after adding
  its plist and icon, and required strict code-sign verification with sealed
  resources before publication. The default is an ad-hoc local signature;
  Developer ID signing and notarization remain separate release steps.
- Integrated app packaging into `build-sfx-macos-zh.sh` while retaining the raw
  single-file executable for terminal use and portability.

Local validation:
- macOS classified the result as `com.apple.application-bundle` with kind
  `Application`; its plist, ARM64 slice, system-only dependency closure, icon,
  bundle identifier, and strict ad-hoc signature all passed inspection.
- The app-contained SFX passed full verification of all 363 manifest entries
  and the complete 2,957,172,396-byte extracted payload.
- A cold launch extracted and published the private cache, and the warm app
  launch reached `Menus/MainMenu.wnd`. LaunchServices started the `.app` by its
  declared executable and it stopped cleanly on `SIGINT`.

The generated app contains locally owned retail assets and remains ignored
under `build/`; it must not be committed or redistributed without rights to all
embedded content and artwork.

## 2026-07-30: Add a deterministic self-extracting game wrapper

Added a Go-based SFX packer and launcher that can package a target-native
GeneralsXZH runtime with locally owned retail assets in one executable.

Packaging and launch design:
- Builds a sorted, deterministic PAX tar stream, compresses it with XZ, records
  per-file and payload SHA-256 values, and embeds it through a private
  temporary copy of the Go module.
- Keeps generated multi-gigabyte payload files out of the source checkout and
  atomically publishes the final wrapper.
- Re-reads every staged file and requires both content hashes and metadata to
  match, rejecting same-size in-place changes during packing.
- Creates the private packer workspace beside the validated output instead of
  under ambient `TMPDIR`, preventing a source tree that contains `TMPDIR` from
  recursively absorbing generated payload data.
- Rejects generated manifests above the launcher's 4 MiB parser limit before
  linking and accepts only the single-stream XZ codec produced by the packer.
- Enforces a 1,900,000,000-byte compressed-payload cap to stay below Go's
  roughly 2 GiB individual embedded-symbol linker limit.
- Launches only on the recorded OS/architecture and passes game arguments
  directly without a shell.
- Places Unix children in a separate process group, forwards `SIGINT` or
  `SIGTERM` exactly once to that group, and reports conventional
  signal-derived exit statuses.

Extraction and cache safety:
- Uses a per-user, content-addressed cache keyed by the payload and manifest
  digests, with private staging, concurrent-first-launch coordination,
  completion markers, full extraction-time hashing, and atomic publication.
- Revalidates the complete tree and every manifest-listed payload regular-file
  SHA-256 on cache hits, including same-size changes to native libraries or
  retail assets.
- Uses two permanent per-content kernel advisory-lock files: an exclusive
  acquisition guard coordinates extraction and purge, a shared runtime lease
  protects the native process lifetime, and process exit releases a crashed
  owner automatically without a stale-lock or heartbeat protocol.
- Rejects traversal, absolute and colliding paths, unsupported filesystem
  objects, escaping or cyclic symlinks, tar/manifest disagreement, and bounded
  resource-limit violations; this includes recursive directory-symlink
  topology and extended Windows device aliases, while Windows payloads reject
  all symlinks.
- Authenticates the complete compressed payload before creating a decoder or
  writing extracted content, accepts one XZ stream, and caps decompressed
  output from manifest-derived tar bounds.
- On Unix, allows `GX_SFX_CACHE` overrides but rejects pre-existing shared
  cache roots instead of changing their permissions; Windows uses the default
  per-user cache because arbitrary DACL ownership cannot be verified.
- Adds `--sfx-info`, `--sfx-verify`, `--sfx-extract`,
  `--sfx-purge-cache`, `--sfx-notices`, and explicit `--` argument
  disambiguation.
- Routes Unix relative asset reads to the immutable payload and relative writes
  to a product-stable `.runtime-state` directory, so GameSpy and DXVK state
  cannot shadow verified loose files or BIG archives.

Platform integration and validation:
- Added a macOS/ARM64 staging script that builds the native bundle, overlays it
  on a private copy of owned retail assets, applies target exclusions, packs
  the wrapper, and applies an ad-hoc local signature.
- Added a Linux/AMD64 staging script that reuses the existing Docker native
  build and dependency bundle, then places the portable `.so` closure under
  the SFX `lib/` directory.
- Both staging scripts reject unsafe output overlap, record reviewable
  pre-exclusion candidate inventories, and validate their complete native
  Mach-O or ELF dependency closures before packing.
- Linux dependency discovery statically parses ELF metadata with `readelf`
  instead of executing staged files through `ldd`, and enforces the documented
  maximum required glibc symbol version of 2.38.
- macOS dylib staging rejects distinct libraries that flatten to the same
  basename, and the SFX is packed, signed with the stable
  `com.generalsx.generalsxzh.sfx` identifier, and verified at a
  same-directory temporary path before replacing the prior artifact.
- The local `5b2bdadb0ed4-dirty` macOS/ARM64 validation artifact contains 363
  entries at 1,780,979,836 compressed bytes and 2,957,172,396 extracted bytes.
  Its ARM64 format, strict ad-hoc signature, SHA-256, and full extraction
  verified successfully; the wrapper hash is snapshot evidence, not a stable
  release checksum.
- Cold and warm-cache macOS launches both reached `Menus/MainMenu.wnd`; the
  warm run omitted the extraction path, mutable DXVK files remained under
  `.runtime-state`, and `SIGINT`/`SIGTERM` produced clean native shutdowns with
  wrapper statuses 130/143.
- The matching Linux/AMD64 validation artifact contains 465 entries at
  1,883,386,056 compressed bytes and 3,333,325,193 extracted bytes. Its static
  AMD64 wrapper, complete native ELF closure, SHA-256, and full extraction
  verified inside the Linux/AMD64 builder container. Graphical gameplay
  remains to be tested on a native Linux/Vulkan host; this Ubuntu 24.04-built
  snapshot requires x86_64 glibc 2.38 or newer.
- The Windows/x86 wrapper can cross-build, but the game remains blocked by
  missing `d3dx8d.dll`; its Bink/Miles stubs export all current imports but
  deliberately leave audio/video behavior unimplemented, and retail-DLL
  compatibility remains unvalidated.
- Small fixtures embedding the current PE32 game entrypoint produced valid
  PE32+ AMD64 and PE32 i386 wrapper executables; this validates the wrapper
  formats only, not Windows gameplay.

Licensing and documentation:
- Embeds the required BSD-style notice for `github.com/ulikunitz/xz` and
  exposes it through `--sfx-notices`.
- Documents first-run behavior, reproducible inputs, verification,
  troubleshooting, the threat model, and the requirement not to redistribute
  retail-backed artifacts without rights.

## 2026-07-29: Port multiplayer discovery and frame-limit fixes

Integrated the functional networking changes from upstream
[LAN PR #181](https://github.com/fbraz3/GeneralsX/pull/181),
[POSIX discovery PR #201](https://github.com/fbraz3/GeneralsX/pull/201),
and this fork's [Apple interface PR #13](https://github.com/ammaarreshi/Generals-Mac-iOS-iPad/pull/13)
without importing their diagnostics, submodule moves, or retail-wire-format
changes.

LAN behavior:
- POSIX LAN receivers now bind to `INADDR_ANY` so broadcasts arriving on
  Wi-Fi or Ethernet are accepted. Debug multi-instance builds retain their
  distinct synthetic `127.x` bind addresses.
- LAN IP enumeration rejects down, loopback, point-to-point,
  non-broadcast, link-local, VPN, AWDL, and common container interfaces.
  The iOS Personal Hotspot `bridge100` interface remains eligible.
- Discovery packets use the selected interface's directed subnet broadcast.
  Post-join game options, readiness, chat, start, leave, and inactivity
  messages use per-peer unicast fan-out.
- Join accept/deny replies remain unicast to the requesting peer instead of
  being converted back into broadcasts.
- POSIX UDP errors now follow the same handling path as Winsock. Bind retries
  close their failed socket first instead of leaking descriptors.

Frame pacing:
- Ported the final behavior from
  [multiplayer FPS PR #230](https://github.com/fbraz3/GeneralsX/pull/230):
  LAN and GameSpy starts no longer disable the user's render cap.
- Initialized the tactical-view time multiplier and fixed the uncapped FPS
  sentinel comparison using upstream commit
  [`0cf00e606`](https://github.com/fbraz3/GeneralsX/commit/0cf00e606c8b10a95d59b377b445d932a5f9b87e).

iOS:
- Added a default-off `GX_IOS_MULTICAST=1` packaging option. It requests and
  verifies `com.apple.developer.networking.multicast`, which physical iOS
  devices require for UDP broadcast.
- The option intentionally fails closed when the signed provisioning shell
  lacks the entitlement. Apple must first approve Multicast Networking for
  the exact explicit App ID and the provisioning profile must be refreshed.

CRC review:
- Reviewed upstream CRC PR #189 and its later `Int`-based mapping. This fork
  already resolves a gameplay player to its network slot before checking
  connectivity, so no conflicting CRC dependency chain was imported.

Validation:
- `cmake --preset macos-vulkan`
- `cmake --build build/macos-vulkan --target z_generals g_generals --parallel 18`
- Deployed Zero Hour to `~/GeneralsX/GeneralsZH`.
- Launched the deployed `GeneralsXZH -win` build through SDL3, DXVK, Vulkan,
  and MoltenVK to a live game window.
- `git diff --check`, iOS entitlement plist validation, packaging-script
  syntax validation, and invalid-option handling all pass.

Remaining live coverage:
- A two-peer macOS/Linux test is still required to prove discovery, normal
  join, chat/readiness/start fan-out, disconnect handling, and a sustained
  no-desync match on a real subnet.
- Debug multi-instance LAN still needs a macOS loopback-alias or transport
  solution for instances after the first; normal release multiplayer is
  unaffected.
- The iOS entitlement path requires an Apple-approved App ID, refreshed
  profile, physical device, and second LAN peer before it can be
  device-verified.
