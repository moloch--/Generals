## 2026-08-05: Add the Automated Build Tool desktop app

Added a cross-platform Wails desktop shell around the existing Go Automated
Build Tool. A no-argument launch now opens a four-step React 19 and HeroUI Pro
wizard for target, owned game files, options, and final review. Passing
`--headless` or another existing builder argument retains the established
terminal parser, output, prompts, and exit status through the same shared Go
pipeline.

The GUI streams real build phases and stdout/stderr, validates host-aware paths,
supports native directory selection, and runs only one cancellable build at a
time. Production builds fail closed if the Wails bridge is unavailable;
synthetic preview data requires an explicit Vite preview mode and cannot report
a packaged build success.

SteamCMD still runs whenever the selected retail files need acquisition or
repair. The desktop app opens SteamCMD in a real native terminal, waits for it,
and resumes the structured build afterward. Password and Steam Guard input
never enters the GUI. Homebrew bootstrap, Rosetta installation, and Linux
package-manager operations use the same terminal boundary when administrator
interaction is required. Private job files, typed purposes, heartbeat failure
detection, Unix process groups, and Windows Job Objects prevent terminal hangs
and keep cancelled compiler, installer, and SteamCMD descendants from running.

Validated frontend type checking, ten unit tests, the production bundle, and a
zero-finding dependency audit; root and desktop Go tests, race tests, vet,
module integrity, and Windows cross-compilation; responsive browser layouts;
and a signed native Apple Silicon Wails app. The packaged macOS window loaded
real Wails defaults, its `--headless --help` output matched the Go command, and
an opt-in native Terminal.app round trip completed with a harmless command.
Linux and Windows native GUI packaging remains delegated to the release matrix
and is not claimed as locally executed.

## 2026-08-05: Release the Automated Build Tool from version tags

Added a dedicated GitHub Actions release lane for the Automated Build Tool.
Exact `vX.Y.Z` tags verify both Go modules and the licensed frontend, then build
the Wails app natively on macOS/ARM64, Linux/AMD64 with WebKitGTK 4.1, and
Windows/AMD64 with embedded WebView2. Every archive also contains a CGO-free
`generalsx-build` headless companion, the project license, and third-party
notices; no retail game data or generated game SFX is uploaded.

The workflow pins actions by full commit, withholds the HeroUI credential from
untrusted pull requests, embeds and verifies desktop tag/commit provenance,
checks headless Go VCS metadata, compares desktop and standalone headless help,
and smoke-runs each native GUI. It generates `SHA256SUMS`, creates a draft
release, verifies the exact four assets and tag commit, and only then publishes.
Manual dispatches build snapshot archives without publishing. Actionlint,
YAML, action-pin, and artifact-policy checks pass locally; the new native matrix
has not yet been executed on GitHub Actions.

The first `v0.0.1` tag run showed that the public npm tarball contains the
HeroUI Pro package shell but not the licensed component payload. The trusted
frontend job now restores that payload explicitly with the HeroUI Pro CLI and
the masked repository credential, then asserts that the Stepper and Radio
Button Group entry points exist before compiling.

The first native matrix then completed the macOS and Linux Wails builds but
exposed two release-runner compatibility checks. Target verification now reads
the binaries' `go version -m` `GOOS` and `GOARCH` settings instead of the plain
toolchain version. Windows Job Object assignment now opens the suspended child
with the documented quota and terminate rights, preserving descendant-safe
cancellation while remaining compatible with the workflow's Go 1.25 baseline.
Both root and desktop Windows packages cross-compile with that exact toolchain.
The Windows headless build also runs from the repository root so Go records the
tagged commit and clean-worktree provenance instead of treating the root module
as an unstamped relative dependency of the desktop module. It runs before the
Wails resource generator so generated Windows packaging state cannot mark that
standalone binary's otherwise clean source tree as modified.
Windows release validation uses the application's explicit embedded version and
commit response because the runner's file-version API returns an empty product
string for Wails' language-neutral PE resource even though the resource exists.

## 2026-08-01: Fix cached Online password handling on Windows

Fixed the shared Generals and Zero Hour Online login preference code so it
transforms the current password byte before advancing its input and key
pointers. The previous combined assignment and post-increment expression wrote
through the advanced pointer under the native MSVC language mode, corrupting
the cached password buffer and crashing while `GameSpyLogin.ini` was loaded.

The replacement preserves the existing reversible on-disk format, including
its deliberate equal-byte handling, and changes neither Online authentication
data nor LAN/local networking. Both macOS game targets and the native Windows
cached-login path were rebuilt for validation.

## 2026-08-01: Fix 64-bit Online lobby selection crash

Fixed a live macOS crash found while validating the deployed Online server with
the packaged GeneralsXZH client. Entering Custom Match refreshed the lobby's
multi-select player list, but the shared list-box message handler narrowed its
selection-array pointer to a 32-bit `Int`. The next UI update dereferenced the
truncated address in `PopulateLobbyPlayerListbox()`.

The list-box API now has a typed multi-select overload and returns the backing
selection array at full pointer width. Updated both games and the shared chat
caller to use that overload so the same unsafe cast cannot recur at those call
sites.
