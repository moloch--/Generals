# Development Diary - August 2026

## 2026-08-01: Fix cached Online password handling on Windows

Fixed the shared Generals and Zero Hour Online login preference code so it
transforms the current password byte before advancing its input and key
pointers. The previous combined assignment and post-increment expression wrote
through the advanced pointer under the native MSVC language mode, corrupting
the cached password buffer and crashing while `GameSpyLogin.ini` was loaded.

The replacement preserves the existing reversible on-disk format, including
its deliberate equal-byte handling, and changes neither Online authentication
data nor LAN/local networking. Both macOS game targets and the native Windows
cached-login path were rebuilt for validation.

## 2026-08-01: Stop repeated Online staging updates

Stopped authoritative game snapshots from re-emitting legacy player-info
callbacks when a member's identity and slot topology are unchanged. This keeps
join, identity, host, slot, and readiness notifications intact while preventing
the host from echoing identical options and chat updates indefinitely.

Validated the complete path with two standalone macOS clients: both signed in,
joined the same custom-match lobby, readied, started Alpine Assault through the
authenticated UDP relay, and exchanged thousands of gameplay datagrams with no
authentication, malformed-packet, rate-limit, or missing-endpoint drops.

## 2026-08-01: Embed a machine-local Online endpoint

Added a build-time Online endpoint for modern clients while retaining the
existing command-line override and explicit LAN transport. CMake keeps the
tracked default empty, generates the value outside the source tree, and can
load a repository-local configuration file that Git ignores. This lets local
standalone binaries open **MULTIPLAYER > ONLINE** against their intended
backend without exposing a deployment address in source control.

The focused endpoint test uses a documentation-only TEST-NET address to cover
compiled-default initialization, runtime override precedence, and restoration
of the built-in value without publishing the real local setting.

Validated the focused test with both configured and empty production headers,
rejected malformed IPv4, DNS, and port values during CMake configuration, and
rebuilt both macOS game targets. Binary inspection confirmed the private local
value is present only in the intended game executables and ignored build state.

## 2026-08-01: Add a tailnet-only Online admin dashboard

Added a bearer-authenticated REST API and HeroUI Pro dashboard for the Online
server. Operators can inspect health, stored profiles, connected players, game
lobbies, and relay counters, then confirm targeted session disconnects or
lobby closures. Large identifiers and counters stay lossless across the JSON
boundary, profile browsing is paginated, and admin actions are covered by the
server's structured audit log.

The dashboard reuses the packaged GeneralsXZH application icon and a consistent
Font Awesome action/status vocabulary across the HeroUI Pro layout, including
accessible empty states and reduced-motion-aware refresh feedback.

The Vite production output is embedded recursively with Go's standard
`embed.FS`, so the static Go binary and scratch container image have no loose
web root or Node runtime. Compose mounts a private bearer-token file and
publishes the admin listener only on an explicitly configured Tailscale IPv4
address; the public gameplay and private health bindings remain unchanged.

## 2026-08-01: Fix 64-bit Online lobby selection crash

Fixed a live macOS crash found while validating the deployed Online server with
the packaged GeneralsXZH client. Entering Custom Match refreshed the lobby's
multi-select player list, but the shared list-box message handler narrowed its
selection-array pointer to a 32-bit `Int`. The next UI update dereferenced the
truncated address in `PopulateLobbyPlayerListbox()`.

The list-box API now has a typed multi-select overload and returns the backing
selection array at full pointer width. Updated both games and the shared chat
caller to use that overload so the same unsafe cast cannot recur at those call
sites.

## 2026-08-01: Defer Online connection until login

Changed the custom Online adapter to open its control connection only when the
player submits Login or Create Account. This removes the server's unauthenticated
idle deadline from the login form, prevents a stale "Lost connection" dialog,
and avoids joining a completed socket worker while the session mutex is held.
Authenticated and in-progress login failures remain visible, while LAN/local
queue selection and networking are unchanged.

Added focused connection-loss policy coverage and a real two-connection native
socket regression that restarts the control client and verifies the exact queued
authentication frame on macOS and MSVC.
