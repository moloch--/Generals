# Development Diary - August 2026

---

## 2026-08-01: Add self-hosted Online multiplayer

Added an opt-in replacement for the retired retail Online service while
preserving the existing Network/LAN implementation. Starting a standalone
GeneralsX or GeneralsXZH build with `-onlineServer <endpoint>` routes
**MULTIPLAYER > ONLINE** to the new service; omitting the flag retains the
legacy behavior.

Server and protocol work:
- Created
  [`moloch--/generals-server`](https://github.com/moloch--/generals-server) as
  an independent Go repository with account and guest authentication, rooms,
  chat, buddies, staged games, Quick Match, results/statistics, health/metrics
  endpoints, and an authenticated UDP game relay.
- Added exact product, Online protocol version, and gameplay INI CRC matching
  for joins and Quick Match. Native executable CRCs are deliberately excluded
  because compatible Windows PE and macOS Mach-O builds are not byte-identical.
- Added a launch barrier: each player receives slot-specific relay credentials,
  acknowledges them over the control connection, and must complete an
  authenticated UDP bind before map loading. A disconnected player's relay
  token is revoked without tearing down an already launched match for the
  survivors.
- Added bounded messages, authentication and relay rate limits, capacity
  limits, timeouts, constant-time credential checks, atomic profile storage,
  TLS 1.2+, Docker Compose, systemd, operational documentation, and protocol
  tests. Gameplay datagrams remain opaque authenticated relay traffic rather
  than end-to-end encrypted traffic.

Client integration:
- Added cross-platform Online endpoint parsing, control-session state, custom
  GameSpy queue adapters, lobby/game/Quick Match event mapping, and a relay
  transport for both Generals and Zero Hour.
- Kept native sockets, resolver calls, TLS, and synchronization in
  `Core/GameEngineDevice/Source/Platform/`; the game layer crosses that boundary
  through platform-neutral relay factories, session helpers, and datagram
  address values.
- Kept the feature behind the Online command-line endpoint so LAN sockets,
  menus, and protocol behavior remain unchanged. The standalone macOS and
  Windows launchers forward the argument to the native game. LAN and GameSpy
  launch sites now choose the legacy or relay transport explicitly, so stale
  Online session state cannot redirect a LAN match.
- Bare endpoints use temporary plaintext guest sessions for local development.
  `tls://` endpoints require verified certificates and hostnames with no
  plaintext fallback; Windows builds use libcurl with Schannel.
- Added operator/player guidance in `docs/HOWTO/ONLINE_MULTIPLAYER.md` and
  documented the standalone Windows `libcurl.dll` and `zlib1.dll` runtime
  closure.
- Gated the replacement client and its C++20 JSON dependency out of the VC6
  reference preset, which retains the original legacy Online implementation.
- Staged the pinned JSON dependency explicitly in both offline Flatpak
  manifests, and restored the existing pinned `stb` source override, so Linux
  distribution builds can configure without network access.

Validation completed locally:
- Go race tests, vet, formatting, Docker Compose validation, a production image
  build, and a container health/metrics smoke test.
- Focused client protocol tests plus complete macOS Vulkan builds of
  `GeneralsXZH` and `GeneralsX`.
- Cross-compiled MinGW i686 Online objects and focused tests, then completed
  native MSVC x86 Release builds of both games. The Windows focused suite ran
  the real Winsock framing and Schannel ClientHello/no-plaintext-fallback
  paths; PE inspection confirmed the standalone `libcurl.dll`/`zlib1.dll`
  dependency plus the three-file VC143 runtime closure, without OpenSSL, and
  the SFX argument-forwarding suite passed.
